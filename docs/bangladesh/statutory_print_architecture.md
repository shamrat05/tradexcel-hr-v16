# Bangladesh statutory print formats - source and implementation design

Status: source inventory and downloader only. **No legally approved print
templates or business-record migrations are implemented by this branch.**

The DIFE Khulna checklist contains **29 linked documents**. Some contain
multiple form variants (notably 35/35(a) and 37/37(a)/37(b)); the final
two are licence and machinery layout *evidence*, not HRMS-generated forms.

- Official index: https://dife.khulna.gov.bd/pages/static-pages/69812dfe35ce18e1c06fa1b0
- Registry: `docs/bangladesh/dife_form_sources.json`
- Downloader: `scripts/download_dife_reference_forms.py`
- Retrieve in a networked environment: `python -m pip install pypdf` then
  `python scripts/download_dife_reference_forms.py --download --output dife_references`
- Each download receipt records SHA256, page count, byte size and failed links.
- A separate manual GitHub Actions run uploads temporary private reference
  artifacts for review; the original PDFs are **not** committed to Git history.

The index was last updated in October 2025. Review the latest applicable
Bangladesh legal amendments, gazettes and sector-specific rules before
marking any form legally current. Establishment licences, EPZ status,
factory equipment and worker classification affect applicability.

## Non-hardcoded design

There are two independent user experiences:

1. **Review / correct**: Native Frappe Report/List using authorized
   Company/Branch scope, period filters, missing-data checks, drill-through
   links, and ordinary export.
2. **Official print / preserve**: A separately reviewed and **versioned**
   Bangla Print Format or file-backed Script Report HTML. Match the prescribed
   columns, orientation, title, pagination and signature/acknowledgment spaces
   to that original PDF. Do not equate a normal report export with Form 34
   or Form 38.

All organization-specific content must be read at render time from the
authorized **Company**, establishment compliance configuration, Employee,
Leave, Attendance and native Payroll records. Never preseed legal entity
names, sites, monthly salaries, wage percentages, NID numbers, deductions,
tax constants, overtime rates or signatories in a shared HTML template.

Before rendering a form, choose the approved combination of
`jurisdiction + establishment + form_id + legal_effective_date + template_version`,
perform permission checks, verify the required native source documents and
reconcile amounts. Never silently assume optional legal data. Record the
form's version, generated by/at, source record keys, approval and filing
evidence without copying sensitive payroll records into public logs.

### Likely source mappings - subject to per-form legal field audit

- **6 / 6a / 7 / 8**: Employee/Company/appointment and issue register.
- **9**: Leave Application/Allocation/Leave Ledger Entry.
- **19**: approved maternity benefit review plus authorized wage evidence.
- **33**: Compensatory Leave Request / native leave ledger.
- **34**: submitted Attendance and approved Overtime Slip. Employee Checkin
  is raw evidence, not proof of approved working time.
- **38**: submitted Salary Slip/Payroll Entry and separately confirmed payment
  or receipt evidence. A posted salary slip does not prove payment.
- **39**: authorized damage/loss deduction decisions and payroll.
- **80 / 81**: establishment-level reconciled returns, including missing
  information alerts.
- **20 / 22 / 22a / 23 / 24 / 25a / 26 / 26a / 27 / 28 / 32 / 35 /
  35a / 36 / 37 variants**: safety, facility, incident, medical or shift
  consent and inspection state often absent from native HRMS; the system
  must request a valid external evidence record rather than fabricate it.
- **Licence and machinery layout**: upload/store original approvals. Do not
  generate a pretend government-issued certificate.

## Form acceptance checklist

For *each* form, independently:

1. Download complete original PDF and record URL/SHA256/page count.
2. Render and inspect every page, **including rotated landscape scans**.
3. Verify the form version and legal applicability with a Bangladesh adviser.
4. Make a per-field map to an authorized Frappe document or new evidence
   DocType only if genuine new state is necessary.
5. Create a versioned app-owned HTML/Jinja print template or report print
   format using Frappe's supported extension APIs; do not patch core.
6. Test Bangla font availability, dates/numerals, multiline employee names,
   long registers, wide grids, repeat headers, zero rows, signatures,
   printing at actual paper size, landscape/portrait and source totals.
7. Perform visual comparison with the original PDF and reconcile sample
   synthetic records independently.
8. Validate least-privilege permissions, field masking, export audit and
   retention. Only then mark the template approved/available.

## Action positioning, minimal navigation

Keep the Frappe v16 sidebar native, not a new global rail. Put:

- Attendance Summary -> **Form 34** under a contextual **Registers** group.
- Payroll Entry -> **Form 38** with a review-and-reconcile step.
- Employee -> **Appointment / Form 6 / Form 7** grouped under **Documents**.
- Leave -> **Form 9** under the native report actions.
- Compliance & Registers workspace -> grouped list of every form, their
  applicability and availability, and a persistent compliance calendar.

Never add 29 separate top-level sidebar items. Forms that are inapplicable
or not yet legally approved should be labeled clearly and **not** offer an
Official Print action.

## Boundaries

This branch contains source links and optional tooling only. It does not
alter Doctypes, permissions, print formats, hooks, salary structures or
production data. Integrating an official form will be a separately reviewed
product change with synthetic tests and a Frappe bench acceptance check.
