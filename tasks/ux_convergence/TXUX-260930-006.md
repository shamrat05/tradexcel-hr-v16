## P01 — native Shift Assignment route filters (review correction)

**Reproduced defect:** the review action passed `from_date` / `to_date` as List View route filters. The installed `Shift Assignment` schema has `start_date` (Date, required) and `end_date` (Date, optional) and no `from_date`/`to_date`; the List View route parser resolves each key through the doctype meta and silently drops unknown fields, so the date narrowing never applied. Adding `end_date >= day` would also wrongly exclude blank, open-ended assignments.

**Mechanism check:** the installed List View route parser (`parse_filters_from_route_options` in `frappe/public/js/frappe/list/list_view.js`) builds AND-only filters and has no `or_filters` support, so the exact “End Date blank OR End Date on/after the day” condition is not expressible through route options. The server-side query builder does support `or_filters`, which the tests use only to define the active-on-day truth — not to pretend the route is exact.

**Final route filters:** `employee: ["in", selected permitted Employee IDs]` and `start_date: ["<=", selected review day]`; no `from_date`, `to_date` or `end_date` key is sent. The operator is explicitly told the list is a broader Start-Date review and that an assignment is active on the day only when End Date is blank or on/after it; the message also says the list contains assignments that already ended. The separate missing / overlapping / default-only / assigned descriptions, the native Shift Assignment Tool (no Employee IDs, no automatic Shift Type), server-side authority and the existing role/scope restrictions are unchanged.

**Tests (P01):** node contract asserts the native `start_date` filter, the absence of `from_date`/`to_date`/`end_date` keys, the End Date/blank/already-ended instruction and that no every-row-is-active claim is made; `test_attendance_shift_recovery_ui.py` proves the schema via `frappe.get_meta("Shift Assignment")`, asserts the installed route parser has no OR support while `db_query` does, and exercises real synthetic assignments inserted on the installed schema — overlapping, open-ended, ended-before and another Employee’s assignment — proving the route filter returns exactly the selected Employee’s three start-before rows (including the ended one) while the exact active-on-day condition returns only the overlapping and open-ended rows. Cleanup resets synthetic `docstatus` and verifies zero residue. Browser: 5 checks (msgprint instruction, footer actions, 1365/375 light/dark, no overflow, exact route filters) with a synthetic persona and zero-residue cleanup. The full #65 regression set (attendance/shift corrections, period controls, bulk integration, shift tool, report scope/authorization/filters) is **47 passed, 0 failed, 0 skipped**.

**Unresolved:** unchanged. The `attendance_corrections._preview_one` native-message issue remains a documented CROSS_SCOPE_DEPENDENCY and that backend service was not edited.

   - Shift Coverage report logic assesses coverage and overlaps strictly against submitted assignments (`docstatus = 1`).

   - Installed List View parser (`parse_filters_from_route_options`) resolves standard fields to the target DocType and creates `[["Shift Assignment", "docstatus", "=", 1]]`.
   - Updated `workforce_shift_coverage.js` navigation options:
     - `docstatus: 1`
     - `employee: ["in", selected permitted Employee IDs]`
     - `start_date: ["<=", selected review day]`

     - Retained ended assignments: previously ended assignments remain visible due to the broader AND-only Start-Date filter;
