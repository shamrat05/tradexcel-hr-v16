## P01 — explicit, safeguarded cleanup contract (supersedes the automatic path)

The reviewed correction: source retirement stays, but database deletion is no longer automatic and no longer relies on module+name alone.

- **Actual cleanup trigger:** ordinary `after_migrate` never deletes retired artifacts. Deletion happens only when an operator deliberately runs `remove_retired_dashboard_artifacts(apply=True, backup_reference=...)` at a separately authorized backed-up deployment checkpoint (e.g. `bench --site <site> execute tradex_hr.install.remove_retired_dashboard_artifacts --kwargs "{'apply': True, 'backup_reference': '20260930_...-database.sql.gz'}"`).
- **Dry-run behavior:** `plan_retired_dashboard_artifacts()` and the default `remove_retired_dashboard_artifacts()` are read-only and return `{removable, retained}` with a reason per retained candidate. No deletion occurs.
- **Live-reference safeguard:** before any deletion (in the plan and again immediately before each delete) every candidate is checked against `tabWorkspace Chart`, `tabWorkspace Number Card`, `tabWorkspace.content` (covers public and private Workspaces), `tabDashboard Chart Link`, `tabNumber Card Link`, `tabCustom HTML Block` html/script/style, `tabDesktop Icon`, `tabWorkspace Sidebar Item` and the supported persisted-user surface `__UserSettings`. Historical `Version`/`UI Version` rows are deliberately excluded as audit history. Any functional reference retains the candidate.
- **Ownership safeguard:** deletion additionally requires an exact match against `RETIRED_ARTIFACT_FINGERPRINTS` — the original installer payloads of the eleven canonical artifacts (module, identity and behaviour fields, `filters_json` compared parsed). A customized or foreign record is retained with the differing field reported. Historical aliases and prototype duplicates have no reliable fingerprint and are always retained rather than guessed.
- **Fail closed:** if a reference surface cannot be inspected, the candidate is retained with the inspection error reported.
- **Backup requirement:** `apply=True` requires a non-empty `backup_reference` (the verified `BACKUPS.md` row) and an Administrator/System Manager session; otherwise it throws and deletes nothing.
- **Idempotency and bounds:** absent names are skipped; a second apply run removes nothing; only exact allowlist names are ever considered.
- **Staging:** a read-only plan was executed against staging: all eleven canonical records match their fingerprints with zero functional references (removable), the three native cards are untouched and outside the allowlist, and nothing was deleted. No backup was needed for the read-only plan.

P01 tests (8 passed): unused identifiable artifact removed; customized same-module artifact retained; foreign-module record retained; referenced artifact retained; uninspectable surface fails closed; absent names harmless; dry-run and ordinary migration never delete (AST-checked); apply requires backup reference and System Manager; fingerprints/allowlist cover only the reviewed canonical artifacts and never the native cards; no retired JSON/creation source remains.

## P02 — Production allowlist enforcement, backup preflight and extended reference audit

Following further safety review, the destructive cleanup facility was hardened against caller injection, unverified backup references, and omitted reference/customization surfaces:

1. **Production allowlist enforcement and separated test injection:**
   - Production entry points `remove_retired_dashboard_artifacts(apply=..., backup_reference=..., backup_checksum=...)` and `plan_retired_dashboard_artifacts()` strictly reject arbitrary caller-supplied candidates or fingerprints via keyword arguments (`TypeError`).
   - Production execution is strictly bound to `CANONICAL_DELETABLE_ARTIFACTS` (the 11 canonical artifacts) and `RETIRED_ARTIFACT_FINGERPRINTS`. Any candidate outside this set is rejected with an explicit retention reason.
   - Historical aliases in `RETIRED_ARTIFACTS` are explicitly retained during dry-run as non-deletable without separately established app ownership.
   - Safe test injection is segregated into dedicated internal helpers (`_plan_retired_dashboard_artifacts_for_tests`, `_remove_retired_dashboard_artifacts_for_tests`), preventing production misuse.

2. **Expanded reference surface inspection & fail-closed dynamic links:**
   - Expanded native reference scanning to cover:
     - `tabWorkspace Sidebar Item`: `url`, `route_options`, and `filters` (JSON string containing artifact links or names).
     - `tabDesktop Icon`: `link`.
     - `tabWorkspace Shortcut`: `link_to`.
     - `tabWorkspace Link`: `link_to`.
   - Dynamic custom field inspection: dynamically queries `tabCustom Field` for custom `Link` fields targeting `Dashboard Chart` or `Number Card` and inspects their tables.
   - Fail-closed dynamic link policy: any custom `Dynamic Link` field in `tabCustom Field` triggers a fail-closed exception, retaining all candidates with an unresolvable reference reason.
   - Documented exclusion: historical `tabVersion` rows are excluded as historical audit logs, not live functional references.

3. **Strengthened customization detection (presentation properties):**
   - Fingerprints extended to verify presentation-critical and behavioral properties against original installer definitions:
     - Number Cards: `background_color`, `show_percentage_stats`, `stats_time_interval`, `show_full_number`, `report_function`, `currency`.
     - Dashboard Charts: `custom_options`, `show_values_over_chart`, `dynamic_filters_json`, `color`, `time_interval`, `timespan`, `timeseries`, `currency`.
   - Value normalizations: parsed JSON filter comparison, integer casting (`cint`), and whitespace stripping ensure exact behavioral match while preventing spurious mismatch on formatting. Any customization causes retention.

4. **Accurate backup verification preflight:**
   - Added `verify_backup_preflight(backup_reference, backup_checksum)`:
     - Requires both `backup_reference` (e.g. filename in `private/backups`) and `backup_checksum` (SHA-256).
     - Enforces filename safety (rejects path traversal `..`, `/`).
     - Verifies site identity matches current active site (`frappe.local.site`).
     - Verifies backup archive existence and non-zero file size on disk in `private/backups/`.
     - Computes streaming SHA-256 and validates against the operator-provided checksum.
   - Clarifies that an arbitrary string does not prove a backup; explicit verified preflight proof is required before any destructive operation.

5. **Accurate evidence & operational status:**
   - Ordinary migration (`after_migrate`) never invokes retired dashboard artifact cleanup (AST-verified).
   - Other existing installer cleanup routines (e.g. guidance/setup) remain intact and operational.
   - Source retirement is tested and complete (no JSON sources, helpers, or recreation paths remain).
   - Real deployed database retirement has **not** occurred on staging or production; no live records have been deleted.
   - Manual cleanup in production requires an independently verified backup archive + SHA-256 checksum and a fresh site-specific reference audit at an authorized maintenance window.
