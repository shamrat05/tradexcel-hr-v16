## Readiness UX result

- **Every distinct blocker is visible.** `_friendly_problem` no longer truncates with “(+ N more issue)”; it lists each server finding in operator language, joined with `·`, while the exact backend codes are preserved in a hidden `blocker_codes` column. Different blocker families are never merged into “Payroll not ready”.
- **Fix scope is explicit.** A new visible `Fix Scope` column classifies the exact codes as `Employee record`, `Company configuration`, `Period`, `Payroll run`, or `Review required` (unknown codes are never guessed). The classification is presentation only and lives in the owned report.
- **Run-level next step.** Failed/Queued/Cancelled managed runs and any run-level financial blocker add a visible `Payroll Run` action that opens the existing native Payroll Entry. The failed-run message still says “Open the Payroll Entry for native retry”.
- **Can-I-proceed answer.** The report message now states “N of M records need attention before preparing” or “N record(s) ready. The server rechecks readiness when you prepare.” The Prepare button remains advisory-disabled by server summary values; the server re-runs `prepare_native_payroll` on click and never trusts a client flag.
- **Money stays server-returned.** `financial_result` renders the native draft Salary Slip values as received; the client never computes gross/deductions/net/tax. Financial columns only exist for roles that can already run the report.
