## Objective, ancestry and files

Resolve the cross-scope dependency recorded in TXUX-260930-006 (section "Cleanup and unresolved"):
When `_preview_one()` in `tradex_hr/tradexcel_hr/attendance_corrections.py` tests an expected row-level skip (e.g., employee already has approved leave, holiday, or attendance status unchanged), native HRMS `AttendanceRequest.validate_no_attendance_to_create()` raises `frappe.ValidationError` and appends a `frappe.msgprint` table to `frappe.local.message_log`. `_preview_one` catches the exception and correctly sets `outcome = "Skipped"`, but the caught message remained in `message_log`, causing Frappe to return `_server_messages` and pop up an unnecessary error modal dialog on desk.

## Defect Investigation and Reproduction

1. **Exact native method emitting the message:**
   `hrms.hr.doctype.attendance_request.attendance_request.AttendanceRequest.validate_no_attendance_to_create()` at lines 49–54 of HRMS:
   ```python
   frappe.msgprint(
       title=_("No attendance records to create due to following reasons"),
       msg=message_table,
       as_table=True,
       raise_exception=True,
   )
   ```
2. **Exception raised:**
   `frappe.ValidationError` with table formatted details.
3. **Intended preview result:**
   Row outcome `row["outcome"] = "Skipped"` with explanatory message `_warning_message({item.get("reason") for item in warnings})`.
4. **Classification:**
   Expected row-level skip, NOT a genuine validation failure or system error.
5. **Message-log lifecycle in Frappe v16:**
   `frappe.msgprint` appends to `frappe.local.message_log`. Whitelisted methods return this list via `_server_messages` in the JSON response, triggering an alert modal on Desk.

## Implementation Details

In `tradex_hr/tradexcel_hr/attendance_corrections.py`:
- Recorded `messages_before = len(getattr(frappe.local, "message_log", []))` before calling `request.validate()`.
- Inside the exception handler, if and only if `warnings and all(item.get("action") == "Skip" for item in warnings)` (the verified expected skip condition):
  - Prunes only the messages appended during candidate validation: `del frappe.local.message_log[messages_before:]`.
- If the exception is due to any other reason (genuine validation failure, unexpected error):
  - Messages are NOT pruned, leaving genuine errors visible.
- No global clearing of `message_log`; pre-existing messages from caller context are preserved.
