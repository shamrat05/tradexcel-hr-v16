## A. Analysis of Ownership Mechanisms

### Mechanism 1: Standard App-Level JSON Export (`<app>/workspace_sidebar/*.json`)
- **Inspection of Frappe v16 core:**
  - `apps/frappe/frappe/desk/doctype/workspace_sidebar/workspace_sidebar.py`:
    - `WorkspaceSidebar.export_sidebar()` exports to `<app>/workspace_sidebar/<title>.json` if and only if `self.app and self.standard and not frappe.flags.in_import and frappe.conf.developer_mode`.
  - **Fatal architectural gap:** Frappe v16 core has **zero** loader or importer code for `<app>/workspace_sidebar/*.json`.
  - Neither `frappe.modules.import_file` nor `frappe.migrate` nor `sync_fixtures` inspects `<app>/workspace_sidebar/`.
  - Creating a standard JSON file does not result in Frappe synchronizing or installing the sidebar on clean setups or upgrades.

### Mechanism 2: Source-Owned Installer Metadata (`ensure_workspace_sidebar` in `install.py`)
- **Execution Lifecycle:**
  - Invoked during `after_install()` for fresh setups.
  - Invoked during `after_migrate()` for version upgrades.
- **Properties:**
  - Sets `standard = 0`, `app = "tradex_hr"`, `module = "Tradexcel HR"`.
  - Fully idempotent across repeated runs.
  - Leaves `for_user = None` (public base sidebar), never interfering with user-specific personal sidebars (`for_user = "<user>"`).
- **Decision:** Retain the supported installer mechanism (`ensure_workspace_sidebar`) as the sole authoritative writer. No competing writers or broken JSON imports.

## B. Customization and Permission Preservation

1. **User Customizations (`for_user`):**
   - Frappe duplicates public sidebars into personal records named `<title>-<user>` with `for_user = "<user>"` when users modify their sidebar.
   - Verified via `test_installer_sidebar_preserves_personal_user_sidebars`: `ensure_workspace_sidebar()` synchronizes only the public `Tradexcel HR` (`for_user is None`) record and leaves user-customized sidebars completely untouched.
2. **Permission-Filtered Navigation:**
   - Sidebar items are standard links (`link_type`: DocType, Workspace, Report).
   - Bootinfo filters items natively through Frappe's `user_perm_can_read` permissions.
3. **Desktop Icon Routing:**
   - `tradex_hr/desktop_icon/tradexcel_hr.json` specifies `"link_type": "Workspace Sidebar"` and `"label": "Tradexcel HR"`.
   - Frappe's native desktop click handler matches `s.label.lower()` to `bootinfo.workspace_sidebar_item["tradexcel hr"]` and routes to the first accessible item.

## C. Collapsed-State Scrollbar Defect Audit

- **Defect Description:**
  When the native Desk sidebar is collapsed, the collapse/expand toggle button and bottom icons can be partially obscured by a vertical scrollbar.
- **Root Cause Analysis (Frappe Native SCSS):**
  - Inspected `apps/frappe/frappe/public/scss/desk/sidebar.scss`:
    - Line 38: `.body-sidebar { width: 50px; ... }` (when collapsed).
    - Line 63: `.body-sidebar-top { overflow-y: auto; ... }`.
  - When the height of the item list exceeds the viewport height in collapsed mode, the browser generates a native vertical scrollbar within the narrow 50px `.body-sidebar-top`.
  - Tradexcel HR has zero custom CSS targeting `.body-sidebar-top` or `.body-sidebar`.
- **Target Assignment:**
  In accordance with `MASTER_PLAN.md` and `OWNERSHIP.md`, this global layout issue belongs to **TXUX-012 (Global UI CSS Containment)**. No global CSS was modified in 011.
  - Proposed native-compatible fix for TXUX-012:
    ```css
    .body-sidebar:not([data-sidebar-expanded="true"]) .body-sidebar-top {
      scrollbar-width: none; /* Firefox */
      -ms-overflow-style: none; /* IE/Edge */
    }
    .body-sidebar:not([data-sidebar-expanded="true"]) .body-sidebar-top::-webkit-scrollbar {
      display: none; /* Chrome/Safari */
    }
    ```
