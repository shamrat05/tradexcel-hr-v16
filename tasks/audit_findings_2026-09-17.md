# Read-only DeepSeek audit register — 2026-09-17

Four concurrent `opencode-go/deepseek-v4.1-flash` source-only reviews examined plan, payroll, Desk/access and SenseFace bridge. Tool permissions allowed read/search only; no agent edited source, called the live site, read credentials or accessed employee snapshots. A human coordinator then checked the findings against the installed Frappe/HRMS and bench-local runner. This is a **first-pass source audit, not an exhaustive or runtime certification**. Paths below are repo-relative unless `sync/` or `apps/hrms/` is stated.

## P0 — block hosting/device exposure and write-agent deployment

1. **Bridge ADMS input is unauthenticated and trusts caller-supplied serial.** Separate bridge `server.py:296-305` accepts `/iclock/cdata` posts and `SN` without checking a known device; the `authorized()` check at `server.py:203-204` is only used by read APIs. If port 8090 is publicly reachable, a remote party could forge punches and device identities. Reject unknown serials, bound body size, put ADMS behind a restrictive ingress/proxy/firewall with tested device protocol authentication where supported, and test spoof/replay. Do not expose this endpoint as-is.
2. **Bridge can overwrite a known person's display name with blank during an ATTLOG post.** Separate bridge `server.py:30-31,135-176`: a line `PIN=1001\t2026-09-17 09:00:00\t...` matches both `ATT_RE` and `USER_RE`. `save_push` scans all lines for USERINFO even when table is ATTLOG; the second pass UPSERTs empty `Name/Pri/Card` and updates existing attendance names to blank. Raw request and punch remain, but derived names/employee metadata can be corrupted. Parse only the declared table, require actual USERINFO fields, preserve non-empty existing metadata, add synthetic regression test and repair preview; no blind live rewrite.
3. **Bridge read API is open if key is unset.** `server.py:24,203-204,253-269` uses empty default `SENSEFACE_API_KEY`; `authorized()` returns true when empty. `/health` at `:240-250` discloses device serial/IP/count even when a key is set. Fail closed for private APIs, protect health, rotate/test key; do not put this process directly on the public internet. `server.py:301-302` also reads unbounded `Content-Length`, permitting memory exhaustion.
4. **Frappe device-control RPCs lack operation-level authorization.** App `tradex_hr/api.py:42-80` whitelists configure and health actions, loads the device and makes remote requests/status writes without an explicit permission check. `:84-149` checks Employee/device **read** but re-enables a biometric assignment via `frappe.db.set_value` (write bypass); transfer `:156-240` checks only read before sending a bridge command. Require explicit narrow IT/HR action permission, company scope, audit, CSRF-safe POST/method restrictions and tests as low-privilege users. Restrict bridge URL targets and redirect behavior to prevent internal-network requests. This is a source-level access gap; actual exploitability depends on live roles/route exposure.
5. **Configure button calls an endpoint absent from the pinned bridge.** App `tradex_hr/api.py:50-53` POSTs `/api/v1/devices/{serial}/configure`; the bridge at `c4839d5` has no such route (its POST handler accepts only `/iclock/*`). A success claim or Contabo device onboarding is false until an agreed bridge contract and real terminal test exist. Likewise verify transfer endpoint support before enabling template transfer.
6. **Migration may delete Frappe's native HR workspace.** `tradex_hr/install.py:653-659,848-852` lists generic `HR` as a legacy workspace and force-deletes every matching workspace at migration. A fresh/reconfigured site could lose the native HR Desk workspace and its links. Scope cleanup to app-owned records with migration evidence; no generic-name force delete. Rehearse on restored staging before any `bench migrate`.

## P1 — payroll/permission correctness before approval

7. **Native worker structure is configured for double proration.** `tradex_hr/tradexcel_hr/payroll_setup.py:40,63-65` defines `base * payment_days` **and** `depends_on_payment_days=1`. Installed HRMS `apps/hrms/hrms/payroll/doctype/salary_slip/salary_slip.py` `update_component_row` and `get_amount_based_on_payment_days` use formula result as `default_amount` then multiply by `payment_days / total_working_days`. For 15 paid days in 30 at Tk 350, this path can yield Tk 2,625 instead of Tk 5,250. The bench-local manual runner takes a different path, so do **not** claim every current draft is wrong; test both native Payroll Entry and manual drafts on a staging site, then choose one calculation owner and reconcile existing slips.
8. **Exception preview and runtime draw from different populations.** `tradex_hr/tradexcel_hr/doctype/tradexcel_policy_exception/tradexcel_policy_exception.py:71-77` previews only `exception_type=Payroll`, but `tradex_hr/tradexcel_hr/payroll_policy.py:61-69` omits type when applying exceptions. If a non-payroll record retains a payroll `field_name`, it may change a wage without appearing in the payroll preview. Filter by type in runtime, validate/clear type-specific fields and test type switching, stale previews and conflicts.
9. **Custom salary hooks discard native row metadata and recalculate totals too simply.** `tradex_hr/tradexcel_hr/component_exceptions.py:181-202` and `tax_exceptions.py:57-64` rebuild rows with only component/abbr/amount, losing flags such as `do_not_include_in_total`, tax/account treatment and links. `deduction_rules.py:79-94` sums all rows; native HRMS `SalarySlip.get_component_totals` excludes `do_not_include_in_total`, while native `set_net_pay` sets other derived fields. This can alter gross/net/tax/account semantics for configured components. Preserve row fields or use native mutation/calculation hooks, then test non-total components, loans, Additional Salary, tax and GL against HRMS.
10. **Employee/Worker ESS permissions are broad on request doctypes.** `tradex_hr/role_setup.py:111-130,207-213` adds non-owner-scoped `EDIT_PERMS` for Leave Application and Attendance Request, while removing Employee read. If that role is assigned, a worker may be able to read/edit colleagues' requests or have an unusable own-request flow; existing site snapshot has zero such assignments, so this is a **future activation risk**, not evidence of an existing data leak. Test own-only, another worker, branch manager, supervisor actor and approver separately; use native permission hooks/User Permissions only if proven sufficient. `approval_setup.py:24-47` also gives HR Manager approve/cancel transitions while `role_setup.py:119-120` grants no submit/cancel on Leave Application; verify workflow transition authority in staging.
11. **App-only checkout cannot reproduce production behavior.** Payroll `sync/run_payroll.py` and device worker `sync/reliable_bridge_worker.py` live outside versioned app. A Contabo checkout of `tradexcel-hr` alone omits them. Package audited runtime and tests, pin bridge service version, use a clean checkout/staging test and keep prototype importers quarantined. This is a deployability gap, not evidence the current local runner never works.
12. **Cross-company report scope needs real authorization tests.** `tradex_hr/install.py:14,124,176,217,268` restricts four raw-SQL reports to System Manager (good short-term containment); native `Report.is_permitted` allows a report with no role rows, and `query_report._run` additionally checks report permission on the reference DocType. Raw SQL itself does not enforce row-level company/branch permissions. `Daily Attendance Summary` is a Script Report whose scope must be checked separately. Do not call all reports leaked: run six-persona view/export tests before opening reports to managers, then move to server-side scoped Script Reports.

## Rejected or narrowed agent claims

- **Not true:** `resolve_policy` has no current caller. Bench-local `sync/run_payroll.py` calls it. The real defect is missing packaging/clean-checkout reproducibility.
- **Not proven:** OT is never paid because structure's OT row is zero. The bench-local runner calculates daily worker OT and adds an Overtime Pay row; edge values and reconciliation still require tests.
- **Not inherently wrong:** the classifier marks non-administration TCL factory staff as workers. That follows the owner's stated default; HR must review named exceptions, not silently recategorize the whole cohort.
- **Not proven:** all reports are exposed. Four new query reports explicitly restrict to System Manager; role-less or script reports still need runtime permission and row-scope tests.

First freeze public bridge exposure and disable false-ready configure/transfer actions; preserve raw evidence. Then make bridge parsing/auth and Frappe RPC permission fixes in isolated branches with adversarial tests. Rehearse migration on a restored site before touching `install.py` behavior. Reconcile worker salary math against the native HRMS path and current drafts before any submission. Package runtime, prove role/company boundaries, then resume the feature gates in `deepseek_v4_1_flash_handoff.md`. No live payroll or biometric data was changed in this audit.
