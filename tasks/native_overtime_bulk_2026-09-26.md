## Installed native behavior and the missing pre-payroll route

Installed HRMS 16.19.0 owns `Overtime Slip` and its detail/Additional Salary calculation in `hrms/hr/doctype/overtime_slip/overtime_slip.py`. Its `filter_employees_for_overtime_slip_creation()` identifies submitted Present Attendance with Overtime Type and excludes overlapping draft/submitted slips. `OvertimeSlip.get_emp_and_overtime_details()` populates native detail rows from submitted Attendance and saves a draft. Native `Payroll Entry.create_overtime_slips()` provides a bulk helper and >30 queue, but only **after a Payroll Entry exists**; it uses the entry's employee child table and sets the entry status after processing. Tradexcel's `inspect_native_payroll_readiness()` blocks unreviewed OT before `prepare_native_payroll()` can create the managed Payroll Entry. Therefore that native bulk button cannot serve the pre-payroll correction sequence without reversing the readiness gate.

A synthetic Tradexcel HR Manager had Overtime Slip create but no Payroll Entry write; Payroll Approver had Overtime Slip submit but no create. A native HR Manager PE control refused write when the synthetic PE contained an out-of-scope child Department. The accepted payroll finalization integration already proves independent Payroll Approver submission of a native Overtime Slip, native Additional Salary provenance, and dual-role maker self-approval denial. No native HRMS source was edited.

## Narrow native-first adapter

`overtime_bulk.py` supplies a read-only preview and draft-only apply for HR Manager. It asks native permission-aware `frappe.get_list("Employee")` for the caller's Company/Branch/Department population, then reuses HRMS' eligibility filter and native `OvertimeSlip.get_emp_and_overtime_details()`. It also requires a submitted effective SSA with explicit Salary Structure pay basis through the existing resolver. Missing authority is a blocked preview row; it never invents an OT rate. Checkin evidence alone is never OT authority.

The Overtime Slip List gains one native-list button. The dialog previews Employee/Branch/Department and qualifying submitted Attendance count; the maker explicitly selects, confirms, and creates draft native Overtime Slips. It neither submits the slip nor calculates money. The separate Payroll Approver uses native Overtime Slip List bulk submit; the existing `before_submit` hook checks independent approval, finalized Attendance, submitted Attendance detail and reviewed Working Time rules before HRMS creates native Additional Salary. The native PE helper remains available to native HRMS roles for their supported workflow; custom HR Manager cannot mutate Payroll Entry merely to reach it.

The existing synthetic payroll finalization fixture was extended with an Administrator cancellation attempt after native Overtime Slip submission and payroll consumption. Before the fix, installed Frappe raised `LinkExistsError` because the submitted native Additional Salary referenced the slip, but the current transaction already held `Overtime Slip.docstatus = 2` when the exception was caught. A narrow `before_cancel` hook now refuses cancellation while an active native Additional Salary references the slip, before Frappe writes the changed status. The regression proves both documents remain submitted. This keeps the native link and native financial records authoritative; no cancellation ledger was added.

Apply re-resolves Employee scope and OT eligibility, rejects a forged/out-of-scope selection before mutation, uses per-Employee savepoints and returns draft/blocked/failed results. Native overlap validation and the preview filter prevent replay. For >30 rows it queues a domain-specific worker. Installed Frappe `frappe.enqueue()` captures the caller's user; the worker additionally checks the saved requester identity and revalidates role, Company/User Permission, salary authority and OT eligibility at execution. If Frappe's internal deadlock retry loses user context, the worker fails closed. No bulk ledger, custom OT calculator or new approval record was added.
